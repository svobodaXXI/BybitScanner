# BybitScanner — проверенный SSH-доступ локальных агентов к VPS

**Зафиксировано:** 28 октября 2026 г.  
**Назначение:** повторить на втором Windows-ПК проверенный доступ с ноутбука, без установки Claude Code на VPS.  
**Статус:** ноутбук — подтверждён успешный вход и проверена кнопка «Состояние» Windows VPS Manager; второй ПК — ещё не настроен.

## 1. Архитектура и границы

- Локальные Claude Code / инструменты управления работают на Windows-ноутбуке и Windows-ПК.
- Подключение к Ubuntu VPS выполняется через OpenSSH, с проверкой ключа хоста (`StrictHostKeyChecking=yes`).
- Исходный код проходит через GitHub; управление PAPER Runtime — отдельно, только с разрешения владельца и с сохранением Admission и STOP/TAKE.
- На VPS **не нужно** устанавливать Claude Code, XFCE, XRDP или Remote Control.
- **LIVE строго запрещён.** SSH-доступ сам по себе не разрешает запускать/останавливать робота, изменять PAPER БД или выполнять deploy.

## 2. Что фактически сработало на ноутбуке

**Ноутбук:** `DESKTOP-DSFV958`. **Текущая учётная запись для повседневной диагностики:** `vpsmanager`. VPS-адрес ниже в командах обозначен `<VPS_IP>`: получать из локально сохранённого ярлыка/настроек, не записывать секреты в Git.

1. В GitHub [issue #631](https://github.com/svobodaXXI/BybitScanner/issues/631) сохранён первоначальный подтверждённый вход 27 октября под `root` с локальным ED25519-ключом `bybitscanner_laptop`, с явным `-i`, `IdentitiesOnly=yes`, `PasswordAuthentication=no` и **интерактивным вводом passphrase**.
2. При повторной проверке 28 октября ввод passphrase во **встроенном терминале агента** некорректно доходил до SSH. В **обычном окне Windows PowerShell** тот же ключ разблокировался и команда вернула `whoami=root`, корректное имя VPS и **exit 0**. Следовательно, повторные ошибки встроенной панели нельзя автоматически трактовать как неверный ключ/пароль или неисправность VPS.
3. Для постоянной работы локального агента на ноутбуке создана **отдельная** пара ED25519 `bybitscanner_vpsmanager` / `.pub`, без passphrase (защита за счёт Windows ACL и ограниченных прав серверной учётной записи). Приватный файл доступен только владельцу Windows-профиля; root-ключ `bybitscanner_laptop` остаётся отдельным.
4. Уже созданному на VPS непривилегированному пользователю `vpsmanager` установлен **только публичный** ключ в `/home/vpsmanager/.ssh/authorized_keys` с префиксом `restrict`. Домашний каталог и `.ssh` проверены, права `.ssh` — `700`, `authorized_keys` — `600`, владелец файла — `vpsmanager`.
5. Фактически проверен вход с ноутбука под `vpsmanager` с `BatchMode=yes`: `whoami=vpsmanager`, корректный `hostname`, команда `true`, **exit 0**. Проброс удалённого порта с ключом `restrict` отклонён.
6. Windows VPS Manager переключён на `vpsmanager` и отдельный ключ. Проверена кнопка **«Состояние»**: `Exit code: 0`; на момент проверки PAPER backend и Telegram `active/running`, одноразовый `paper-start` `inactive/dead` (это не свидетельство остановки PAPER-ядра). Остальные кнопки необходимо проверять отдельно.

**Важно:** `restrict` ограничивает PTY, порт-форвардинг, agent/X11 forwarding, но **не создаёт allowlist удалённых команд**. `vpsmanager` должен оставаться без общих `sudo`-прав. Не добавлять без отдельного согласования в `sudo`, `docker`, `systemd-journal` и другие группы расширенного доступа.

## 3. Два уровня подключения

### А. Рабочий канал агента — `vpsmanager`

Пример **без сохранения адреса в Git** (выполняет локальный агент; `<VPS_IP>` подставляется из локальной конфигурации):

```powershell
ssh -i "$env:USERPROFILE\.ssh\bybitscanner_vpsmanager" -o IdentitiesOnly=yes -o BatchMode=yes -o PasswordAuthentication=no -o StrictHostKeyChecking=yes vpsmanager@<VPS_IP> "whoami; hostname; true"
```

Проверять код возврата (`$LASTEXITCODE` должен быть `0`). Не считать подключение подтверждённым по одному сообщению `Server accepts key`.

### Б. Резервный административный канал — `root`

Использовать только для заранее согласованных действий. Ключ ноутбука `bybitscanner_laptop` зашифрован; **не применять `BatchMode=yes` для интерактивного ввода passphrase**, если ключ не разблокирован в `ssh-agent`.

```powershell
ssh -i "$env:USERPROFILE\.ssh\bybitscanner_laptop" -o IdentitiesOnly=yes -o PasswordAuthentication=no -o StrictHostKeyChecking=yes root@<VPS_IP>
```

Для ввода passphrase использовать обычное окно PowerShell, а не панель терминала агента. **Не публиковать** passphrase, приватный ключ или секреты в чате, логах, GitHub и скриптах.

## 4. Windows SSH Agent

На ноутбуке служба `ssh-agent` была включена в режим **«Вручную»** и запущена. **Ключи в неё не добавлялись**; это не препятствует входу с отдельным незашифрованным ключом `vpsmanager`.

Не делать предположение, что автозапуск `ssh-agent` обеспечивает сохранение загруженного ключа после перезагрузки. Не помещать root-ключ в агент автоматически без отдельного разрешения: это расширяет возможность административного входа для процессов от имени Windows-пользователя.

## 5. Windows VPS Manager

- Репозиторий: `svobodaXXI/BybitScanner`.
- Базовая версия: PR [#662](https://github.com/svobodaXXI/BybitScanner/pull/662).
- Исправления SSH identity и запуска через `--host`, `--user`, `--key`: PR [#663](https://github.com/svobodaXXI/BybitScanner/pull/663), зафиксирован коммит `0ede4a01` в отчёте агента.
- На ноутбуке EXE собирался локально и установлен с резервной копией прошлой версии. **Наличие локально установленной версии не означает, что PR влит в stable.**
- Локальный ярлык передаёт адрес VPS, `vpsmanager` и путь к ключу; серверный адрес не требуется встраивать в исходники.
- Подтверждена только функция **«Состояние»**. Для чтения журнала/Git могут потребоваться дополнительные права; не выдавать их автоматически.

## 6. Как позднее настроить второй ПК

1. На **втором ПК** создать **собственную** пару ED25519 для `vpsmanager` с новым именем, например `bybitscanner_vpsmanager_pc`. **Не копировать приватный ключ ноутбука** и не использовать старые ключи от исторического VPS.
2. Локально проверить fingerprint, приватный файл и Windows ACL (доступ только нужному пользователю). Не отправлять приватный файл на VPS, в GitHub или чат.
3. Через уже работающий, отдельно разрешённый администраторский SSH-доступ с ноутбука добавить **публичную** часть ключа ПК отдельной строкой `restrict ssh-ed25519 ...` в `/home/vpsmanager/.ssh/authorized_keys` с сохранением остальных ключей. Не переписывать файл целиком. Проверить владельца и права.
4. На **ПК** выполнить **одну** проверку подключения с собственным ключом под `vpsmanager`, `BatchMode=yes`, `StrictHostKeyChecking=yes`, `whoami`, `hostname`, `true`, exit `0`.
5. Только после этого установить/настроить Windows VPS Manager на ПК; указать в локальном ярлыке тот же VPS и **ключ ПК**, проверить кнопку «Состояние» и фактический exit `0`.
6. Если вход не проходит: сначала разделить стадии `Offering public key`, `Server accepts key`, локальная подпись и `Authenticated to`; не запускать длинный цикл создания новых пользователей, сброса паролей или переустановки VPS.
7. Не менять `sshd_config`, не перезагружать VPS, не трогать PAPER Runtime и не добавлять новые полномочия без отдельного разрешения.

**Критерий завершения переноса на ПК:** с ПК подтверждён `vpsmanager`, hostname нужного VPS, `true`/exit `0`, а Windows VPS Manager показывает успешный результат «Состояние». До этого считать ПК неподключённым.

## 7. Уроки инцидента

- **Результат важнее диагностики.** Не подменять успех сообщениями `Server accepts key` или успешным копированием файлов.
- Встроенный терминал агента и обычный PowerShell не равнозначны для защищённого интерактивного ввода.
- `BatchMode=yes` удобен для **уже разблокированных или незашифрованных** ключей, но может блокировать интерактивную passphrase.
- Сначала читать issue [#631](https://github.com/svobodaXXI/BybitScanner/issues/631) и [VPS lessons](https://github.com/svobodaXXI/BybitScanner/blob/stable/adfb50b-forward/DOCUMENTS/VPS_PAPER_TELEGRAM_ONE_BUTTON_LESSONS_20261027.md); только потом менять доступ.
- Не делать ежедневную работу через root. Отдельный непривилегированный пользователь и отдельный ключ на каждую Windows-машину.
- Для торговой системы не путать `systemctl active` с готовностью Scanner/Robot, состоянием защиты позиций или разрешением PAPER_AUTO.
