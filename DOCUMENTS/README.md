# README.md

# BybitScanner

Автоматический аналитический сканер торговых структур для рынка Bybit.

---

# 1. О проекте

BybitScanner — это система технического анализа, предназначенная для поиска потенциальных торговых возможностей на основе:

- графических моделей;
- геометрии цены;
- структуры движения;
- подтверждающих факторов;
- системы оценки качества сигнала.

Проект не является торговым роботом.

Он:

- не открывает сделки;
- не управляет капиталом;
- не принимает финансовые решения.

Его задача:

```
найти → проанализировать → оценить → уведомить
```

# 3. Основная идея проекта

Рынок формирует структуры.

Задача BybitScanner:

1. получить данные;
2. найти потенциальную структуру;
3. проверить её математически;
4. оценить качество;
5. дождаться подтверждения;
6. отправить уведомление.

# 5. Основные модули

## main.py

Главная точка запуска.

Отвечает за:

- запуск сканирования;
- управление процессом;
- вывод результатов.

Не содержит:

- математических расчётов;
- логики паттернов.

---

# analyzer

Отвечает за анализ одной торговой пары.

Задачи:

- загрузка свечей;
- подготовка данных;
- запуск анализа;
- сбор результата.

---

# geometry

Главный математический слой.

Отвечает за:

- построение линий;
- поиск Apex;
- анализ Compression;
- анализ Touches;
- проверку структуры.

---

Структура:

```
geometry/

├── engine.py
├── trendline.py
├── apex.py
├── compression.py
├── touches.py
│
└── validation/
    ├── geometry.py
    ├── apex.py
    ├── compression.py
    ├── slopes.py
    └── touches.py
```

---

# signal

Отвечает за:

- качество сигнала;
- фильтрацию;
- торговую оценку.

Не содержит:

- построения графиков;
- работы с API.

Проект поддерживает разные режимы анализа.

```

```

и

```

```

---

## Hunter

Более широкий поиск.

Цель:

найти больше потенциальных структур.

---

## Sniper

Более строгий режим.

Цель:

меньше сигналов,

но выше качество.

# 9. Geometry Engine

Основной принцип:

сначала математика,

потом торговая логика.

---

Geometry Engine отвечает только за:

- форму;
- линии;
- сжатие;
- касания;
- валидность структуры.

---

Он НЕ должен отвечать за:

- Telegram;
- Score;
- торговые решения.

---

---

# 11. Score System

Оценка качества состоит из компонентов:

```
Structure Score

+

Compression Score

+

Touches Score

+

Confirmation Score

+

Market Score
```

---

Score не должен использоваться для построения геометрии.

---

# 12. Confirmation Engine

После нахождения структуры система проверяет:

## Breakout

Есть ли выход из структуры.

---

## Retest

Есть ли подтверждение уровня.

---

## Volume

Есть ли поддержка объёмом.

---

## Volatility

Есть ли достаточное движение.

# 16. Правила разработки

Основные правила:

1. Один модуль — одна ответственность.

2. Анализ отделён от уведомлений.

3. Геометрия отделена от торговых решений.

4. Старые интерфейсы сохраняются при возможности.

5. Большие изменения сначала документируются.

6. Перед изменением архитектуры обновляется документация.

7. Рабочее состояние проекта регулярно сохраняется.
