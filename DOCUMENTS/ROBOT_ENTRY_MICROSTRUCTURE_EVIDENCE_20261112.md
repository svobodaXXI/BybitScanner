# Единый Robot: поиск импульса и OI для виртуальной торговли

**Владелец:** 12.11.2026. **Статус:** экспериментальная реализация в draft PR #1025, результаты независимой проверки доходности отсутствуют.
**Главный исследовательский пример:** ICNTUSDT, 07.11.2026, 14:00–14:16 МСК.
**Связанные источники:** `TRADING_STRATEGY_SPEC.md` H-017/H-018, не объединённый PR #321 о forced-flow exhaustion.

## Единственный торговый механизм

Scanner обнаруживает формацию, Robot использует свои исходные FSM, ретест, расчёт LIMIT, риск, STOP/TAKE и защиту. Общий модуль `robot_entry_flow_evidence.py` добавляет **экспериментальный предикат допуска защищённого входа** по реальной ленте taker-исполнений и, по выбору, 5-минутному открытому интересу. Симулятор вызывает тот же код Robot и обычный виртуальный исполнитель с комиссиями, сделками и P&L; второй механизм входа не создаётся.

Никакого отдельного режима наблюдения без сделок для этой гипотезы нет. Факторы проверяются **на разнице результатов виртуальной торговли**, а не на количестве обнаруженных маркеров.

Варианты одного и того же прогона:

- `oi_mode=OFF`: отбор по ленте и реакции цены без дополнительного OI.
- `oi_mode=RISING`: вход только при установленном росте OI.
- `oi_mode=FALLING`: вход только при установленном снижении OI.

Эти режимы — **исследовательские группы**, а не заявка, что рост OI всегда лучше падения, или наоборот. Если активирован фильтр OI, но данных нет, они устарели либо причинная последовательность нарушена, **новая виртуальная сделка не разрешается**. Отсутствие данных не трактуется как нулевой OI.

## Причинность и источники

1. Биржевые taker Buy/Sell нормализуются одинаково для официальных Bybit CSV и WebSocket. Архив исходных исполнений должен соответствовать закреплённому SHA-256 торговой истории; источник и непрерывность проверяются, будущие минуты недоступны.
2. Пятиминутный OI поступает из локального CSV `simulator-v2-data/oi-history/{SYMBOL}.csv` (например, `ICNTUSDT.csv`). Нужны `timestamp_ms`, `open_interest_base`, `source=Bybit V5 public open-interest API`, `native_interval=5min`. Поле имени символа отсутствует в исходном исследовательском CSV, поэтому файл жёстко привязан к имени тикера. Чтение ограничено 8 МБ / 40 000 строками; SHA-256 входного CSV сохраняется в отчёте. Эта привязка и SHA гарантируют воспроизводимость локального ввода, **но не доказывают подлинность источника самостоятельно**.
3. Для защиты от lookahead каждый OI snapshot считается известным не ранее `timestamp_ms + 300000` (консервативное допущение об окончании интервала), используются только две последние соседние завершённые точки; пропуски и устаревание не интерполируются. В реальной торговле будущий адаптер обязан учитывать фактическое время доставки API, а не переносить предположение из архива.
4. Рост OI показывает изменение **суммарного числа открытых контрактов**, не доказывает открытие новых LONG или наличие ликвидаций. Снижение может сопровождать закрытия LONG/SHORT. Классификация требует цены, Delta, стакана, а для гипотезы ликвидационного каскада — отдельной проверяемой ленты ликвидаций.

При отсутствии исходных архивных принтов используется прежняя стратегия локальной Симуляции без нового фильтра. Фильтр OI требует действительного потока сделок.

## Проверка качества входов

Использовать одинаковые торговые инструменты, комиссии, защиту и отрезки данных. Сравнить три группы (`OFF`, `RISING`, `FALLING`) на ICNT и независимых положительных/ложных импульсах: число виртуальных входов, STOP/TAKE, net P&L, expectancy в R, MAE/MFE, пропущенную прибыль и просадку. Нельзя подбирать параметры на проверочной выборке. Пользовательская оценка проводится на локальном ПК/ноутбуке.

**Граница развёртывания:** PR #1025 черновой. На ПК пользователя новый пакет ещё не установлен; на VPS этот механизм не публикуется. Ни LIVE, ни текущие PAPER runtime, DB, admission и защищённые обязательства не меняются. VPS — только после независимого положительного результата и отдельного разрешения владельца.
