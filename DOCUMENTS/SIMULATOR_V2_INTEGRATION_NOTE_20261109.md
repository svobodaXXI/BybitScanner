# Симулятор 2.0 — отдельная разработка, обязательная будущая стыковка

**ВНИМАНИЕ: ОБЯЗАТЕЛЬНО ОБЪЕДИНИТЬ С «МАШИНОЙ ВРЕМЕНИ» H-017, КОГДА ОБЕ ЧАСТИ БУДУТ ГОТОВЫ. НЕ СОЗДАВАТЬ ДВА КОНЕЧНЫХ СИМУЛЯТОРА.**

Решение владельца: 09.11.2026. Статус: **изолированная параллельная разработка, не установленный продукт**.


### ОБЯЗАТЕЛЬНО: только виртуальная демоторговля, никаких биржевых ордеров

**Указание владельца 09.11.2026:** симулятор предназначен **исключительно для торгов на собственном виртуальном счёте SIMULATION** по историческим свечам. Это не счёт Bybit MAIN, не PAPER, не Bybit testnet/demo-account и не любой иной подключённый биржевой счёт. «Демо» означает **внутреннюю полностью симулируемую торговлю без реальных или удалённых биржевых торговых операций**.

- Исторические рыночные данные допускается получать из **публичного read-only market API** или локального кэша. Приватные trading/order/account endpoints, торговые ключи, authenticated sessions, отправка/отмена/изменение ордеров и внешние исполнения — запрещены при любом режиме и независимо от выбранного UI-счёта.
- Для каждого прогона создаётся независимый **виртуальный баланс и журнал SIMULATION**: только виртуальные позиции, исполнения, комиссии, equity, realized/unrealized PnL и отчёты. Никаких записей, импорта или агрегации в журналы PAPER/MAIN/testnet.
- При будущей стыковке с настоящим кодом Scanner/Robot переиспользовать их **логику решений**, но все команды исполнения направлять **только** в симуляционный адаптер. Любое случайное обращение к приватному биржевому API, PAPER/runtime state или неопознанному торговому адаптеру — fail-closed.
- Критерий приёмки: доказать отсутствие вызовов внешних торговых API и изменений торговых счетов/хранилищ на сквозном прогоне; виртуальные PnL и сделки никогда не описывать как реальные.

### Переиспользование без дублирования

- Модель свечи: **импорт** `research.historical_market_replay.Candle`, не собственная модель.
- Закрытая H1: **импорт** `research.historical_candle_feed.ClosedHigherTimeframeFeed`; для входа M1 добавляется только отсутствующая минимальная M1→M5 агрегация.
- Трендовая геометрия H-017: позднее подключить действующий `research.causal_trend_geometry` **как готовый модуль**, не переписывать.
- Будущие паттерны Scanner: вызывать **их существующие детекторы и фактическую оркестрацию**, включая Mirror/Box и наследование происхождения; не заменять на собственные `PatternAdapter → EntryIntent` стратегии из закрытого [PR #961](https://github.com/svobodaXXI/BybitScanner/pull/961).
- Robot: переиспользовать настоящие policy/admission/entry/protection/lifecycle механизмы; заменить только источники рыночных данных/часов, безопасно изолированные зависимости от постоянного состояния и внешний exchange adapter. **Не подключать действующий PAPER runtime к лаборатории**.
- Изолированный `research/simulator_v2/virtual_account.py` уже содержит **только бухгалтерский read-model** собственного SIMULATION-счёта: явные виртуальные `VirtualFill`, баланс, среднюю цену, реализованный и плавающий PnL, комиссии, equity, исторические snapshots. Исполнителя ордеров, лимитной/маржинальной модели и интеграции Robot в этом модуле **нет**. Будущий симулированный exchange adapter будет производить квитанции для этого read-model; никакой второй бизнес-логики Robot.

### Текущий маленький срез Симулятора 2.0
**Проверенный переход к реальным рыночным данным (09.11.2026).** GitHub Actions [42678175587](https://github.com/svobodaXXI/BybitScanner/actions/runs/42678175587) успешно скачал один официальный публичный архив сделок Bybit `BTCUSDT2026-10-01.csv.gz`, из которого построено 1440 последовательных **производных** минутных свечей. Данные и SHA-256 зафиксированы в архивном артефакте CI; в однодневном SIMULATION-прогоне без стратегии число виртуальных fills=0. Импортёр `research/simulator_v2/trade_archive.py` позволяет складывать такие строго проверенные дни в существующий M1-кэш по идентификатору источника с отпечатком сырого архива. **Не называть агрегированные из сделок OHLCV оригинальными Bybit Kline; не объявлять этот прогон проверкой PnL/доходности Robot.** Никаких удалённых торговых API или изменений H-017 нет. Публичный v5 Kline в предыдущем CI ответил HTTP 403; сетевой архивный smoke после подтверждения переведён в opt-in, а не в регулярный CI.

`research/simulator_v2/report.py` строит **отчёт исключительно по закрытым M1** из проверенного архива: виртуальные Net PnL, equity, комиссия, доходность, максимальная историческая просадка, ежедневные точки и происхождение блоков. Отсутствующий блок при офлайн-прогоне — ошибка без сетевого fallback. Временная ручная схема ордеров предназначена только для проверки бухгалтерии; это **не тест прибыльности стратегии**, пока настоящий Scanner/Robot не подключён через изолированную границу.


`research/simulator_v2/virtual_exchange.py` реализует минимальный **внутренний** исполнитель уже одобренных модельных MARKET-заявок: виртуальный fill по открытию следующей M1, фиксируется после её закрытия, комиссии передаются в существующий `VirtualAccount`. Это только сменный адаптер будущего Robot, **не** второй набор торговых правил и **не** точная биржевая микроструктура. Ограничения первой модели: одна ожидающая заявка; нет LIMIT, частичных fills, плеча, STOP/TAKE и модели проскальзывания. Production Scanner/Robot не вызываются; соединение с их оригинальными policy/entry/protection/exit отложено до отдельного изолированного моста.


`research/simulator_v2/history.py` загружает строгую закрытую M1-историю порциями, `research/simulator_v2/cache.py` хранит **только публичные исторические свечи** в отдельно выделенном локальном каталоге с проверкой SHA-256 и provenance. Повреждённый архив останавливает прогон, не подменяется данными автоматически. Это кэш рынка, **не** журнал симуляционных сделок, PAPER/MAIN либо хранилище робота.


`research/simulator_v2/timeline.py` — чистый in-memory поток, умеет:
1. Принимать ровно один исторический M1-тикер в одном `simulation_run_id`, проверяя непрерывность закрытых минут.
2. Публиковать M5 и H1 лишь после полного закрытия; H1 переиспользует существующий агрегатор.
3. Последовательно вызывать **только явно переданные** обработчики SCANNER → ROBOT → EXCHANGE. По умолчанию они **не подключены**, торговых решений или исполнений нет.
4. На ошибке остановить переход, не публикуя события и не передавая следующую минуту; после исправления повторить ту же минуту. Обработчики при будущем подключении обязаны быть идемпотентны по виртуальному шагу.
5. Хранить SIMULATION-события и предоставлять read-only проекцию по прошлому UTC-курcору, не меняя/не удаляя журнал при перемотке.

**Не реализовано этим срезом:** реальный Scanner/Robot bridge, полный виртуальный exchange lifecycle (пока реализован только изолированный MARKET fill по следующей M1), сохранение SIMULATION-журнала сделок/состояния на диск, повторное восстановление состояния кампаний и позиций, веб-интерфейс, тесты месячных прогонов. Не выдавать работающий market-only поток за полноценный backtest.

### Обязательная будущая интеграционная задача

После независимого завершения и пользовательской приёмки H-017:

1. Сравнить совпадение формата свечей, временных границ и событий на одинаковом архиве; переиспользовать работающий H-017 UI/geometry, не копировать их.
2. Подключить реальные Scanner/Robot через узкие адаптеры данных/времени и отдельный SIMULATION exchange backend, без production runtime и без фальсификации событий.
3. Обеспечить атомарный журнал обработанного шага и неизменность состояния при rewind; затем свести H-017 и 2.0 **в один локальный запуск и один интерфейс**.
4. Подтвердить равенство результатов пошагового/ускоренного прогона и отсутствие изменений PAPER-данных/файлов/ордеров. Только после этого решать интеграционный PR.

Это задача **по стыковке**, а не разрешение на merge, deploy, торговлю или вмешательство в прототип. До неё обе ветки не должны править одни и те же файлы.
