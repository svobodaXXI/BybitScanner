# BybitScanner — Testing Guide

Версия документа: 1.0  
Дата актуализации: 2026-07-25

---

# 0. Назначение документа

Этот документ описывает правила тестирования проекта BybitScanner.

Он определяет:

- порядок проверки изменений;
- обязательные проверки после рефакторинга;
- контрольные точки стабильности;
- способы поиска ошибок.

---

# 1. SOURCE OF TRUTH REFERENCE

Главный источник правил проекта:

```
PROJECT_RULES.md
```

Все тестирование должно соответствовать:

- архитектуре проекта;
- правилам разработки;
- принципу разделения ответственности.

---

# 2. Главный принцип тестирования

Основной принцип:

```
Изменение считается успешным только после проверки результата.
```

---

Недостаточно:

- код написался;
- ошибка исчезла локально;
- модуль импортируется.

Необходимо убедиться:

- pipeline работает;
- данные проходят через систему;
- результат корректен.

---

# 3. Уровни тестирования

Проект использует несколько уровней проверки:

```
Level 1

Syntax Check

↓

Level 2

Module Check

↓

Level 3

Pipeline Check

↓

Level 4

Logic Validation

↓

Level 5

Regression Check
```

---

# LEVEL 1 — Syntax Check

Цель:

проверить отсутствие ошибок Python.

---

Команда:

```
python -m compileall .
```

---

Проверяет:

- синтаксис;
- ошибки импорта;
- повреждённые файлы.

---

# LEVEL 2 — Module Check

Цель:

проверить отдельные компоненты.

---

Проверяются:

## Geometry

```
geometry/
```

---

## Analyzer

```
analyzer/
```

---

## Telegram

```
telegram_bot.py
telegram_formatter.py
notification_manager.py
```

---

Проверить:

- импорт;
- доступность функций;
- корректность структуры.

---

# LEVEL 3 — Pipeline Check

Главная проверка системы.

Запуск:

```
python main.py
```

---

Ожидаемый процесс:

```
Start

↓

Load symbols

↓

Get candles

↓

Find pivots

↓

Geometry analysis

↓

Pattern detection

↓

Score

↓

Notification
```

---

# Контрольные точки

После запуска проверить:

## Данные

Есть ли свечи?

---

## Pivot

Найдены ли точки?

---

## Geometry

Построены ли линии?

---

## Pattern

Есть ли классификация?

---

## Score

Есть ли итоговая оценка?

---

## Telegram

Отправляется ли сообщение?

---

# LEVEL 4 — Logic Validation

Проверка правильности результата.

---

Для Geometry:

Проверить:

```
upper_line

lower_line

apex

compression

touches

validation
```

---

Для Pattern:

Проверить:

```
Falling Wedge

Rising Wedge

Triangle Compression
```

---

Для Signal:

Проверить:

```
score

confirmation

status
```

---

# LEVEL 5 — Regression Check

После изменений убедиться:

старые функции продолжают работать.

---

Особенно после:

- рефакторинга;
- переноса файлов;
- изменения структуры данных.

---

# 4. Проверка Geometry Engine

Geometry является критическим слоем.

После изменения геометрии проверить:

---

## Trendline

Проверить:

- линия строится;
- slope корректный;
- intercept корректный.

---

## Apex

Проверить:

- существует;
- находится в допустимой области.

---

## Compression

Проверить:

- значение положительное;
- соответствует структуре.

---

## Touches

Проверить:

- количество касаний;
- распределение касаний.

---

## Validation

Проверить:

- почему структура принята;
- почему структура отклонена.

---

# 5. Проверка после изменения Validation

Обязательный порядок:

```
Изменение Validation

↓

Запуск main.py

↓

Сравнение результатов

↓

Проверка ложных отказов

↓

Проверка ложных сигналов
```

---

Нельзя оценивать Validation только по количеству найденных сигналов.

Важно:

```
качество > количество
```

---

# 6. Проверка Telegram

После изменения Telegram слоя проверить:

---

## Formatter

Получает:

```
signal
+
status
```

---

Возвращает:

```
готовый текст
```

---

## Bot

Проверить:

- отправку текста;
- отправку изображения.

---

## Manager

Проверить:

- NEW;
- STRENGTHENING;
- WEAKENING;
- CONFIRMED.

---

# 7. Проверка новых функций

Перед добавлением функции:

определить:

```
какой слой отвечает?
```

---

Пример:

Добавление ATR:

Правильно:

```
market/analyzer
```

---

Неправильно:

```
telegram_bot
```

---

# 8. Проверка больших изменений

После крупных изменений необходимо:

1. Создать архив.

Пример:

```
BybitScanner_backup_DATE_STAGE.zip
```

---

2. Обновить:

```
PROJECT_STATE.md
```

---

3. Обновить:

```
CHANGELOG.md
```

---

4. Создать новый snapshot.

---

Notification
