# Синхронизация ПК с GitHub включает контроль Git-долгов

Статус: правило владельца, 2026-10-23. Применяется к BybitScanner при запросах «синхронизируй ПК с GitHub» и аналогичных действиях.

## Обязательная часть каждой синхронизации

1. Безопасно сверить целевую ветку GitHub и соответствующую установку ПК (HEAD, ahead/behind), не затрагивая пользовательские файлы или другие worktrees.
2. В рамках того же задания выполнить **соразмерный контроль долгов**, используя существующий отчёт/инвентарь: сколько открытых PR, какие ветки и worktrees остаются незавершёнными, есть ли новые бесхозные/неопубликованные изменения, какие задачи зависли и требуют интеграции, закрытия или решения владельца. Проверять изменение относительно последнего достоверного состояния; не запускать полный аудит при отсутствии обоснованного повода.
3. Сообщить владельцу **простым языком** отдельно: (а) синхронизирована ли основная установка; (б) сколько долгов осталось и что среди них важно; (в) какой ближайший безопасный шаг сокращает долг. Не объявлять весь репозиторий «приведённым в порядок», если выполнено только обновление HEAD.
4. Для каждого завершённого изменения доводить относящийся к нему PR и ветку до ясного конечного состояния по существующему GitHub workflow. Предупреждать владельца о значительном накоплении незавершённых PR/веток, а не ждать специального вопроса.
5. Разграничить **проверку** и **исполнение**. Запрос на синхронизацию разрешает контроль долгов и отчёт, но сам по себе не разрешает merge, закрытие PR, удаление веток/worktrees или разрешение конфликтов. Такие действия требуют конкретной авторизации и действующих safety gates; «э» в ответ на непосредственно предложенное действие трактуется согласно правилу разрешений.
6. Сохранять все уникальные коммиты, dirty worktrees, локальные изменения, runtime-данные и файлы запуска. Не применять destructive reset/clean, force push или массовую очистку. Системные изменения в торговом runtime запрещены без соответствующего отдельного разрешения.

**Критерий отчётности:** «Синхронизация выполнена; контроль долгов проведён; остаток и дальнейшее действие названы» либо прямо указано, что именно проверить не удалось. Нулевое расхождение HEAD с origin само по себе не означает нулевой долг.

Это правило дополняет `DOCUMENTS/GITHUB_FIRST_WORKFLOW.md`, `DOCUMENTS/ASSISTANT_PROTOCOL.md` и root `AGENTS.md`; не отменяет их требований безопасности или границ разрешений.
