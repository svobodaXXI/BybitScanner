# AUTOPILOT — Reuse Terminal Chart/DOM and Preserve Scanner Signal Context

Date: 2026-09-08
Status: ACTIVE / DESIGN-ONLY
Implementation authorization: NONE

## Decision

The AUTOPILOT page reuses the existing trading-terminal chart and order book (DOM) components instead of introducing a separate charting or DOM implementation.

For the initial AUTOPILOT version, manual chart controls are intentionally reduced:
- no ticker switching controls;
- no timeframe switching controls;
- no drawing-tool controls.

These controls may be added later, but are not part of the initial AUTOPILOT scope.

## Signal-bound chart context

The AUTOPILOT chart is bound to the active scanner signal/trade context.

The chart must display:
- the ticker associated with the active signal/position;
- the timeframe on which the scanner found the signal;
- the pattern geometry / pattern lines generated by the scanner for that signal.

The scanner must pass the signal visualization context into AUTOPILOT so that the pattern drawn by the scanner is reproduced on the AUTOPILOT chart rather than reconstructed manually from the UI.

## Live trading visualization

The reused chart and DOM remain live execution surfaces for observation:
- active/pending orders are visible on the chart where applicable;
- fills and order-state changes are visible in the existing terminal visualization model;
- the DOM shows live order-book activity and the robot's own order interaction using the same established terminal semantics.

## Intent

The AUTOPILOT view should let the operator see, in one place:
1. the original scanner setup that caused the trade to exist;
2. the live market around that setup;
3. how the robot's orders are being placed and executed.

This keeps scanner signal context authoritative and avoids diverging chart implementations between Terminal and AUTOPILOT.
