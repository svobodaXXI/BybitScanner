# ⚔️ «Катапультирование» — план разработки и проверки гипотез

**Статус:** RESEARCH ONLY. Источник задания — [#1306](https://github.com/svobodaXXI/BybitScanner/issues/1306) и уточнения владельца 24.11.2026. Разрешены проектирование, исследовательский код и офлайн-тесты. **Не разрешены** изменения PAPER/STOP/TAKE, runtime, VPS, merge или LIVE. Согласно strategy-hypothesis-capture, это MECHANICS_REFINEMENT существующих setup, а не новый H-ID. Гипотезы остаются NEEDS VALIDATION.

## Целевой результат

Один штатный Robot, один владелец позиции, общие данные и единая ордерная последовательность:

1. **«Охота за импульсом»** — качественный вход при исходно подтверждённом сценарии.
2. **«Катапультирование»** — сокращение или полное закрытие позиции, когда импульс не развивается либо структура разрушается.
3. **«Честный безубыток» + trailing** — защита уже полученного результата и поддержание остатка при устойчивом движении.

Приоритет — уменьшение суммы фактических отрицательных net PnL и тяжёлых STOP-исходов. Контрольный veto — потери прибыльных сделок, ухудшение общего net PnL, комиссии, проскальзывание и непокрытая защита.

## Контекст из Рашке/Коннорса

Девять предоставленных владельцем скриншотов: печатные страницы 3, 5–9, 11–13. Принципы: сначала ограничивать риск; иметь исходный STOP; признавать несостоявшуюся краткосрочную сделку без ожидания STOP; не превращать краткосрочную идею в бессрочную; поэтапно закрывать прибыль и трейлить STOP; учитывать сильную кульминацию и возврат после ложного пробоя. Это *гипотезы*, а не подтверждение их эффективности на Bybit.

**Типы реакции не смешивать:**
- PROBE: проба экстремума / возможный ложный пробой.
- TREND_RETEST: откат и восстановление в сохраняющемся тренде.
- EXHAUSTION: кульминация/истощение, требующая подтверждения, а не угадывания пика.

Сценарий, trade ID, направление, исходный R, структурный уровень и плановый горизонт замораживаются до входа. Универсальный таймер для всех паттернов не вводить. Правила Turtle Soup далее первой страницы главы на скриншотах отсутствуют — не додумывать.

## Режимы будущего управления после подтверждённого входа

- **Нет продолжения:** индивидуальный timeout для типа setup + минимальный MFE в R. Выход до штатного STOP — только кандидат на исследование.
- **Встречное давление:** устойчивый принт-дельта/скорость сделок/ликвидность/поддержка уровня; single print не определяет разворот.
- **Прибыль, но затухание:** тестировать reduce-only partial: условные 25%, 50%, адаптивные ступени, остаток сохраняет подтверждённый STOP/TAKE; проектируемый net > 0 с консервативными расходами не гарантирует прибыльный fill.
- **Сильное структурное опровержение:** исследовать полный reduce-only выход даже при текущем плюсе.
- **Импульс сохраняется:** исследовать tighten-only STOP по R, swing, ATR/волатильности; отдельный режим climax/range expansion с частичной либо полной фиксацией, сравнивая с обычным trailing.
- **Неясные или устаревшие данные:** никаких новых катапультирований/подтягиваний; исходная защита остаётся активной.

При конфликте существующие protective/emergency/reconciliation intents приоритетны. Один trade owner, один реальный оператор ордеров, одна версия команды. Нельзя одновременно исполнять полный выход и частичный, повторять partial после рестарта, расширять STOP либо оставлять часть позиции без покрытия.

## Реально первый исследовательский срез

Файлы в данном PR: research/simulator_v2/catapult_exit_study.py и tests/test_simulator_v2_catapult_exit_study.py. Они формируют **неисполняемые** предложения по синтетически проверяемым as-of данным; возвращают namespace SIMULATION_RESEARCH_ONLY и trading_authorized=False. Preview защитного STOP не округлён по tickSize и никогда не должен подаваться в торговый Robot. Нет нового биржевого подключения/SQL/записи/сервиса. CI-область — существующий Simulator V2 isolated unit tests.

Существующий сохранённый ICNTUSDT 2026-11-11 archive имеет source-only L2/publicTrade и отрицательный для sustained absorption зафиксированный Box-интервал, но не подтверждает реальный approved Robot host и связанный вход/комиссию/receipt. Предыдущее Wedge BE исследование имело ноль подходящих native завершённых сделок на проверенных диапазонах. Поэтому **экономическую эффективность сейчас вычислить и подтвердить нельзя**. Синтетические unit tests доказывают только механику, а не уменьшение убытков. Исторические host receipts нельзя восстановить из venue event time. Для реальных экономических тестов нужен приватный, отдельно разрешённый read-only доступ к связанной фактической истории и полноте событий; если её не существовало — только prospective capture внутри штатного Robot с отдельной authority.

## Завершение

Заявлять успех только при реальной frozen когорте, воспроизводимых paired fills с затратами и независимом holdout, сокращении убытков **без ухудшения общего net PnL**. Ни PR, ни unit CI, ни merged code не считаются trading acceptance или XP. Финальные merge/deploy/STOP/START/изменение PAPER требуют отдельных разрешений.
