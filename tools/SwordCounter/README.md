# SwordCounter («Мечи»)

**SwordCounter («Мечи»)** — независимая утилита для автоматического подсчёта рабочих объёмов при ручной торговле через MetaScalp на Bybit.

## Статус

- S1 (готово): read-only модуль чтения открытых позиций Bybit — `bybit_positions.py`.
- S2 (готово): расчёт мечей — `swords.py`.
- S3 (готово): компактное окно Windows — `app.py`, `view_model.py`, `settings_store.py`.
- S4 (готово): общий запуск «MetaScalp + Мечи» — `launcher.py`, `create_desktop_shortcut.ps1`.

## Общий запуск «MetaScalp + Мечи» (S4)

Один ярлык запускает два независимых приложения и не ждёт их завершения. MetaScalp запускается из своей установки
`%LOCALAPPDATA%\MetaScalp\current\MetaScalp.exe` без аргументов (как его собственные ярлыки), SwordCounter — через `pythonw` из `venv`.

- Если MetaScalp уже запущен, второй экземпляр не создаётся, запускается только SwordCounter. Если SwordCounter уже запущен, он не запускается повторно (защита именованным мьютексом сеанса пользователя, она же работает при запуске через `start_sword_counter.bat`).
- Если не удалось определить, запущен ли MetaScalp, второй экземпляр не запускается. Неизвестный путь MetaScalp — блокер: ничего не запускается, показывается сообщение.
- Права администратора не требуются. Ключи API не передаются ни в ярлыке, ни в аргументах; MetaScalp получает окружение без переменных `SWORDCOUNTER_BYBIT_API_*`.
- Существующие ярлыки и настройки MetaScalp и BybitScanner не изменяются.

Создание ярлыка на рабочем столе (из корня репозитория, где лежит `tools\SwordCounter`):
`powershell -NoProfile -ExecutionPolicy Bypass -File tools\SwordCounter\create_desktop_shortcut.ps1 -PythonW <путь к venv\Scripts\pythonw.exe> [-DryRun]`.
Скрипт не перезаписывает уже существующий ярлык «MetaScalp + Мечи» и проверяет созданный ярлык чтением обратно. Ярлык хранит путь к папке репозитория: после переноса или удаления worktree пересоздайте его из нового корня.
Пробный запуск без запуска приложений: `venv\Scripts\python.exe -m tools.SwordCounter.launcher --dry-run`.

## Запуск окна (S3)

1. Один раз задать ключ Bybit с правом только чтения в переменных пользователя Windows:
   `setx SWORDCOUNTER_BYBIT_API_KEY <ключ>` и `setx SWORDCOUNTER_BYBIT_API_SECRET <секрет>`, затем открыть новое окно консоли.
2. Запуск: `tools\SwordCounter\start_sword_counter.bat` (без консоли, через `venv\Scripts\pythonw.exe`) или `venv\Scripts\python.exe -m tools.SwordCounter` из корня репозитория.

Окно «SwordCounter» всегда поверх остальных, с кнопками «свернуть» и «закрыть», независимо от MetaScalp:
- верхняя строка `1 РО = 5 USDT` и шестерёнка настроек справа;
- «⚔ Свободно» — крупное зелёное число, «⚔ Задействовано» — крупное красное число;
- при превышении лимита показано фактическое число задействованных мечей.

Позиции читаются сразу при запуске и затем каждые 10 секунд в фоновом потоке. Вместо чисел показывается «Нет соединения» (ошибка Bybit или нет ключей), «Недоступно» (маржа неизвестна), «Нет данных» (нет нового результата дольше 30 секунд) или «…» (загрузка и пересчёт после смены настроек). Устаревшие числа как актуальные не показываются.

Настройки (шестерёнка): «Всего мечей» — целое положительное число, по умолчанию 20; «Стоимость 1 РО» — целое число USDT, по умолчанию 5, дробный ввод округляется математически (0.5 вверх). Сохраняются в `%APPDATA%\SwordCounter\settings.json`, вне репозитория; ключи API туда не пишутся.

## Расчёт мечей (S2)

- По умолчанию 20 мечей по 5 USDT; оба параметра задаются в `SwordSettings` (целое > 0 и положительная сумма USDT).
- Занятая маржа = сумма `positionIM` всех открытых позиций.
- Задействовано = ⌈занятая маржа / размер меча⌉; свободно = max(0, всего − задействовано). Превышение не скрывается: задействовано может быть больше 20, свободных тогда 0, `over_limit=True`.
- Только `Decimal`.
- «Недоступно» без чисел: если у любой открытой позиции маржа неизвестна, отрицательна или не в USDT (USDC не пересчитывается в USDT).
- «Нет соединения» без чисел: при любой ошибке чтения Bybit (API, HTTP, сеть, ответ, ключи).

## Границы

- Независима от Scanner, Robot, Autopilot, PAPER DB и LIVE-контура BybitScanner и не изменяет их.
- Только чтение: один подписанный `GET /v5/position/list` (официальный Bybit V5). Ордера не отправляются и не меняются.
- Ключи API не хранятся в репозитории и не попадают в лог.
- Подписанный запрос уходит только на официальные хосты `api.bybit.com`, `api.bytick.com` (mainnet) и `api-testnet.bybit.com` (testnet), только по HTTPS, без порта, учётных данных, пути и параметров в адресе. Редиректы не выполняются. Недопустимый адрес отклоняется до подписи и отправки запроса.

## Ключи API

Задаются переменными окружения (используйте ключ только с правом чтения):

- `SWORDCOUNTER_BYBIT_API_KEY`
- `SWORDCOUNTER_BYBIT_API_SECRET`

```python
from tools.SwordCounter.bybit_positions import Credentials, fetch_open_positions

positions = fetch_open_positions(Credentials.from_env())
```

Каждый вызов читает текущее состояние биржи и ничего не сохраняет, поэтому после перезапуска приложения достаточно вызвать его снова.

## Подтверждённые поля Bybit (документация V5, Get Position Info)

| Поле API | Смысл | Использование |
|---|---|---|
| `size` | размер позиции, всегда ≥ 0; `0` — пустая позиция | строки с `0` отбрасываются |
| `side` | `Buy` (лонг) / `Sell` (шорт), у пустой позиции `""` | обязателен для открытой позиции |
| `positionIdx` | 0 one-way, 1 и 2 — ноги hedge-режима | вместе с `symbol` — ключ позиции |
| `avgPrice`, `markPrice`, `positionValue` | цена входа, маркировочная цена, стоимость позиции | как есть |
| **`positionIM`** | **начальная маржа (то же значение, что `positionIMByMp`; считается по mark price)** | **занятая маржа** |
| `positionMM` | поддерживающая маржа | информационно |
| `leverage` | плечо позиции | только информационно, в расчёт маржи не входит |
| `positionBalance` | помечено как deprecated, «см. `positionIM`» | не используется |
| `tradeMode` | помечено как deprecated, всегда 0 | не используется |

Занятая маржа = `positionIM`, как её отдаёт Bybit. Она **не** вычисляется как `positionValue / leverage`.

## Ограничения расчёта

- `positionIM` считается по mark price, поэтому меняется вместе с ценой, а не равна марже по цене входа.
- В режиме Portfolio Margin Bybit возвращает `positionIM` и `leverage` пустыми: значение остаётся `None` (`margin_available == False`), число не подставляется.
- В документации не сказано, включает ли `positionIM` маржу, добавленную вручную в изолированную позицию (`positionBalance` устарело и отсылает к `positionIM`).
- Cross-маржа учитывается по позициям, а не на уровне аккаунта.
- Читаются линейные контракты (`category=linear`), расчётные монеты USDT и USDC. Inverse и опционы не читаются.
- Модуль проверен тестами на подменённых ответах. Живой запрос с реальным ключом ещё не выполнялся.

## Ошибки

Нулевое число позиций возвращается только для корректного успешного ответа с пустым списком. Ошибка API (`retCode ≠ 0`, HTTP-статус, таймаут, сеть, повреждённый ответ или нечитаемая строка позиции) приводит к исключению `BybitPositionsError`, а не к пустому результату. Для адресов из США и материкового Китая Bybit отвечает 403.
