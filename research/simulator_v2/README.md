# Simulator 2.0 — изолированный исследовательский подпроект

> **ОБЯЗАТЕЛЬНАЯ СТЫКОВКА:** в будущем объединить с текущей «Машиной времени» H-017 **в один симулятор**, не клонировать её движок. [Решение и границы](../../DOCUMENTS/SIMULATOR_V2_INTEGRATION_NOTE_20261109.md) · [основная спецификация, PR #960](https://github.com/svobodaXXI/BybitScanner/pull/960).

**Пока:** работаем только здесь, на отдельной ветке, не меняем `research/local_replay_viewer/` и файлы H-017. GitHub-merge и установка в ПК/VPS запрещены без соответствующей приёмки/разрешения.

Следующий независимый компонент — `virtual_account.py`: **внутренний виртуальный счёт** с явно задаваемым депозитом; он принимает только подтверждённые `VirtualFill(namespace="SIMULATION")` и вычисляет среднюю цену, количество, реализованный PnL, комиссии, нереализованный PnL и equity по заданной закрытой рыночной цене. Историческая проекция не меняет журнал. Дубли fills, чужой run/symbol, неизвестные комиссии, превышение виртуального баланса и неявный переворот позиции отклоняются. Здесь **нет** метода создать/отправить реальный либо виртуальный ордер: фактическая моделирующая биржа будет отдельным адаптером, без дублирования торговой логики Robot. Текущий баланс **не объявляется свободной маржой**: плечо, обеспечение, ликвидация и доступный объём пока не моделируются.

Первая реализуемая часть — `timeline.py`: событийный источник **закрытых M1**, вычисленные закрытые M5/H1, строгий шаг Scanner→Robot→Exchange только при переданных обработчиках и журнал `SIMULATION` для read-only rewind. Это **не** новый детектор, Robot, торговый исполнитель или пользовательский интерфейс. По умолчанию торговых callbacks нет, а реальные Scanner/Robot не импортируются.

Следующий компонент — `history.py`: **чтение только публичной истории M1**, без подписанных запросов и приватных торговых API. Загрузчик использует `GET https://api.bybit.com/v5/market/kline` с `interval=1`, принимает явно заданный UTC-интервал `[start_ms, end_ms)`, проверяет границу последней закрытой минуты, постраничную хронологию, полную непрерывность и противоречивые дубликаты. Каждая завершённая порция содержит источник и SHA-256 фактически загруженных свечей. По умолчанию порция — 1440 минут (сутки); последовательная выдача без буферизации всех 30/90 дней. Для offline-тестов и локальных архивов допустим инъецированный read-only fetch callback; `source_id` должен честно отражать происхождение данных. Ошибки/пропуски не подменяются свечами. Полный пользовательский запуск пока отсутствует; кэш и отдельный архивный импорт описаны ниже.

Дисковый кэш: `cache.py` хранит **только проверенные публичные OHLCV M1** в явно заданном отдельном каталоге Симулятора 2.0, по ключу тикера, UTC-интервала и исходного `source_id`. Полный блок проверяется при чтении (SHA-256, порядок M1, OHLCV, границы, версия формата); повреждённый файл блокирует прогон, а не заменяется молча. При промахе используется тот же `history.iter_closed_m1_chunks`, после проверки пишется временный файл с атомарным размещением готового блока; повторный запуск читает кэш без запросов к Bybit. Нет общей БД и никакого доступа к счётам или торговому API. Предполагается **один пишущий процесс на выделенный каталог**; многопроцессная координация в этом исследовательском срезе не реализована.

Реальная история без приватного API: `trade_archive.py` локально читает публичные архивы сделок Bybit для linear-контрактов (`public.bybit.com/trading/{SYMBOL}/{SYMBOL}{YYYY-MM-DD}.csv.gz`), **не** смешивая их с официальными Kline. На каждый полностью проверенный UTC-день создаётся ровно 1440 `Candle`; отсутствие хотя бы одной торговой минуты, чужой тикер, чужая дата или повреждённый архив блокируют прогон без заполнения пробелов. Для произвольных совпадающих timestamp порядок сделок определяется стабильным ID; такие OHLCV считаются **агрегированными из сделок**, не доказанной точной копией биржевых свечей. `import_trade_day_into_cache` повторно использует `cache.py`, изолируя данные по SHA-256 исходного файла; `run_cached_archive(source_id=chunk.source_id)` затем воспроизводит их строго офлайн без сети. Исходный архив и его полный SHA-256 сохранять как provenance, не подменять источником `BYBIT_PUBLIC_V5_M1`.

Виртуальное исполнение: `virtual_exchange.py` — **одна изолированная модель MARKET/GTC LIMIT**, использующая тот же `VirtualAccount`, а не второй движок. `MarketRequest` исполняется по OPEN следующей закрытой M1. `LimitRequest` остаётся активной между M1 до отмены, изменения цены или модельного исполнения: покупка — OPEN ≤ LIMIT либо LOW строго ниже LIMIT; продажа — OPEN ≥ LIMIT либо HIGH строго выше LIMIT. Равное касание одной тенью не считается гарантией исполнения. Исполнение по цене LIMIT без искусственного улучшения, комиссия taker при рыночном OPEN и maker при внутрисвечном прохождении; OHLC **не содержит реальной очереди/очерёдности сделок**, поэтому это только явно описанная упрощённая модель. Запись `VirtualFill` и переход минутных часов остаются fail-closed при отказе бухгалтерии; дубли order IDs, смешение MARKET/LIMIT, некорректные amend/cancel и пропуски M1 блокируются. Одновременно допускается одна ожидающая заявка, без частичных исполнений, плеча/маржи, STOP/TAKE и биржевой API. Опциональный `ReadOnlyWedgeRobot` использует **исходные** чистые функции Robot для пробоя/ретеста и построения LIMIT-плана, но **НЕ отправляет** его на исполнение: отсутствуют необходимый защищённый admission, размер в реальных единицах контракта, RR/STOP/TAKE и полная модель риска. Только вручную заданные тестовые заявки можно исполнить в SIMULATION; это **не** доказанный PnL реальной стратегии клиньев.

Сквозной минимальный контур: `session.py` соединяет существующие `IsolatedTimeline`, `VirtualExchange` и `VirtualAccount` **без новых детекторов или торговых решений**. После каждой закрытой M1 сначала отрабатывает последняя стадия `EXCHANGE`, затем публикуется минутный журнал и снимок виртуального счёта. Внешний тестовый вызов `submit(MarketRequest)` разрешён только после зафиксированного закрытия M1; исполнение происходит по open следующей M1. Синхронность часов проверяется, ошибка бухучёта блокирует публикацию следующей минуты и новые заявки; отмена неисполненной заявки и повтор той же свечи предусмотрены. В журнал `IsolatedTimeline` записывается подтверждённое `VIRTUAL_MARKET_FILLED` с количеством/ценой/комиссией; события подачи/отмены хранятся пока отдельно в `VirtualExchange.events`. Сквозного долговременного журнала пока нет.

Отчёт по архиву: `report.py` предоставляет `run_cached_archive(...)` — **строго офлайн**-прогон только по уже сохранённым и проверенным блокам M1 (без сетевого fallback), и `run_verified_chunks(...)` для потоковых источников `HistoryChunk`. В результате `ReplayReport.to_payload()` доступны начальный депозит, итоговые баланс/equity, реализованный/нереализованный Net PnL, комиссии, доходность %, максимальная просадка % по закрытиям M1, число виртуальных исполнений, открытая позиция/ожидающий виртуальный ордер, ежедневная equity и SHA-256 всех входных блоков. Ошибка, пропуск, повреждение или смена источника останавливает прогон; полноценный отчёт не выдаётся. `order_schedule` — только **явный тестовый сценарий** с командами по времени закрытия M1, не стратегия и не доказательство доходности Robot. Если заявок нет, отчёт показывает ноль сделок и ноль торгового PnL, без выдуманных сигналов. Для реального анализа стратегии необходим будущий адаптер действующей логики Scanner/Robot.

Повторное использование действующего исследовательского детектора: `session.py` поддерживает **опциональное** `enable_reused_geometry=True`. Тогда `reused_geometry.py` читает **без изменения** исходный `research.causal_trend_geometry.CausalGeometryFeed` из существующего H-017-research и предоставляет снимки `ReusedGeometrySnapshot` после закрытых M5/H1. Подготовка следующего состояния выполняется на копии; если виртуальная биржа отказывает в обработке M1, состояние геометрии отбрасывается, а повтор той же минуты не даёт лишнего pivot. `projection_at(utc_ms)` возвращает прошлый снимок без изменения текущего состояния. По умолчанию функция **выключена**, поэтому прежние долгие M1-прогоны неизменны. Исследовательская геометрия **не** записывается в журнал как события production Scanner, **не** генерирует сигналы/решения Robot и **не** создаёт заявки. Её производительность для длительных многомесячных прогонов отдельно не подтверждена; реальный Scanner/Robot/admission/STOP/TAKE пока не подключены. Это первый изолированный факт повторного использования, **не полноценная стратегия**.

**Важно:** этот компонент не подключает фактический Scanner/Robot и не является полноценным Robot backtest. Перед будущим подключением Robot потребуется доказать согласованность его admission/exit/protection и атомарность всех побочных эффектов на единой границе виртуального шага; отсутствие этой границы запрещает прямой вызов production runtime.

Переиспользуем `research.historical_market_replay.Candle` и `research.historical_candle_feed.ClosedHigherTimeframeFeed`. Любые будущие интеграции реальных Scanner/Robot должны иметь изолированное состояние, виртуальное время, идемпотентность, fail-closed barrier и отсутствие доступа к настоящим биржевым ордерам/PAPER.

Прицельные тесты: `python -m unittest discover -s tests -p 'test_simulator_v2_*.py'`. Они используют фикстуры, отдельный временный кэш и не требуют торговых ключей, запущенных сервисов или сети.

**Не объявлять полноценной симуляцией:** есть только изолированный учёт переданных виртуальных fills, но пока нет подключённых настоящих стратегий, полного виртуального биржевого движка, пользовательской приёмки длительного прогона и UI; технический 30-дневный прогон реальной истории подтверждён отдельно.
