# Simulator 2.0 — изолированный исследовательский подпроект

> **ОБЯЗАТЕЛЬНАЯ СТЫКОВКА:** в будущем объединить с текущей «Машиной времени» H-017 **в один симулятор**, не клонировать её движок. [Решение и границы](../../DOCUMENTS/SIMULATOR_V2_INTEGRATION_NOTE_20261109.md) · [основная спецификация, PR #960](https://github.com/svobodaXXI/BybitScanner/pull/960).

**Пока:** работаем только здесь, на отдельной ветке, не меняем `research/local_replay_viewer/` и файлы H-017. GitHub-merge и установка в ПК/VPS запрещены без соответствующей приёмки/разрешения.

Следующий независимый компонент — `virtual_account.py`: **внутренний виртуальный счёт** с явно задаваемым депозитом; он принимает только подтверждённые `VirtualFill(namespace="SIMULATION")` и вычисляет среднюю цену, количество, реализованный PnL, комиссии, нереализованный PnL и equity по заданной закрытой рыночной цене. Историческая проекция не меняет журнал. Дубли fills, чужой run/symbol, неизвестные комиссии, превышение виртуального баланса и неявный переворот позиции отклоняются. Здесь **нет** метода создать/отправить реальный либо виртуальный ордер: фактическая моделирующая биржа будет отдельным адаптером, без дублирования торговой логики Robot. Текущий баланс **не объявляется свободной маржой**: плечо, обеспечение, ликвидация и доступный объём пока не моделируются.

Первая реализуемая часть — `timeline.py`: событийный источник **закрытых M1**, вычисленные закрытые M5/H1, строгий шаг Scanner→Robot→Exchange только при переданных обработчиках и журнал `SIMULATION` для read-only rewind. Это **не** новый детектор, Robot, торговый исполнитель или пользовательский интерфейс. По умолчанию торговых callbacks нет, а реальные Scanner/Robot не импортируются.

Следующий компонент — `history.py`: **чтение только публичной истории M1**, без подписанных запросов и приватных торговых API. Загрузчик использует `GET https://api.bybit.com/v5/market/kline` с `interval=1`, принимает явно заданный UTC-интервал `[start_ms, end_ms)`, проверяет границу последней закрытой минуты, постраничную хронологию, полную непрерывность и противоречивые дубликаты. Каждая завершённая порция содержит источник и SHA-256 фактически загруженных свечей. По умолчанию порция — 1440 минут (сутки); последовательная выдача без буферизации всех 30/90 дней. Для offline-тестов и локальных архивов допустим инъецированный read-only fetch callback; `source_id` должен честно отражать происхождение данных. Ошибки/пропуски не подменяются свечами. Дисковый кэш и полный пользовательский запуск пока отсутствуют.

Дисковый кэш: `cache.py` хранит **только проверенные публичные OHLCV M1** в явно заданном отдельном каталоге Симулятора 2.0, по ключу тикера, UTC-интервала и исходного `source_id`. Полный блок проверяется при чтении (SHA-256, порядок M1, OHLCV, границы, версия формата); повреждённый файл блокирует прогон, а не заменяется молча. При промахе используется тот же `history.iter_closed_m1_chunks`, после проверки пишется временный файл с атомарным размещением готового блока; повторный запуск читает кэш без запросов к Bybit. Нет общей БД и никакого доступа к счётам или торговому API. Предполагается **один пишущий процесс на выделенный каталог**; многопроцессная координация в этом исследовательском срезе не реализована.

Виртуальное исполнение: `virtual_exchange.py` — **только локальный MARKET-адаптер**, который принимает уже одобренную симуляционную заявку `MarketRequest`. Заявка, созданная после закрытия M1, получает модельное исполнение по **open следующей M1** только после подтверждения её закрытия; результат — `VirtualFill` в существующем `VirtualAccount`, с настраиваемой комиссией. Учитываемое время исполнения — закрытие следующей M1 (не выдаётся за биржевое подтверждение по реальным часам). Повторные ID, параллельные заявки, пропуски минут, отрицательные суммы и отказы бухучёта блокируются. Это сознательно **ограниченная модель**: только одна ожидающая заявка, без limit/partial fills, плеча/маржи, STOP/TAKE, проскальзывания и интеграции с фактической стратегией Robot. Нельзя подавать произвольную заявку от имени production Scanner/Robot; будущий мост обязан соблюдать их реальные admission и lifecycle.

Сквозной минимальный контур: `session.py` соединяет существующие `IsolatedTimeline`, `VirtualExchange` и `VirtualAccount` **без новых детекторов или торговых решений**. После каждой закрытой M1 сначала отрабатывает последняя стадия `EXCHANGE`, затем публикуется минутный журнал и снимок виртуального счёта. Внешний тестовый вызов `submit(MarketRequest)` разрешён только после зафиксированного закрытия M1; исполнение происходит по open следующей M1. Синхронность часов проверяется, ошибка бухучёта блокирует публикацию следующей минуты и новые заявки; отмена неисполненной заявки и повтор той же свечи предусмотрены. В журнал `IsolatedTimeline` записывается подтверждённое `VIRTUAL_MARKET_FILLED` с количеством/ценой/комиссией; события подачи/отмены хранятся пока отдельно в `VirtualExchange.events`. Сквозного долговременного журнала пока нет.

**Важно:** этот компонент не подключает фактический Scanner/Robot и не является полноценным Robot backtest. Перед будущим подключением Robot потребуется доказать согласованность его admission/exit/protection и атомарность всех побочных эффектов на единой границе виртуального шага; отсутствие этой границы запрещает прямой вызов production runtime.

Переиспользуем `research.historical_market_replay.Candle` и `research.historical_candle_feed.ClosedHigherTimeframeFeed`. Любые будущие интеграции реальных Scanner/Robot должны иметь изолированное состояние, виртуальное время, идемпотентность, fail-closed barrier и отсутствие доступа к настоящим биржевым ордерам/PAPER.

Прицельные тесты: `python -m unittest discover -s tests -p 'test_simulator_v2_*.py'`. Они используют фикстуры, отдельный временный кэш и не требуют торговых ключей, запущенных сервисов или сети.

**Не объявлять полноценной симуляцией:** есть только изолированный учёт переданных виртуальных fills, но пока нет подключённых настоящих стратегий, полного виртуального биржевого движка, принятого длительного сквозного прогона и UI.
